# 代码规范

适用于工作站的源码、测试、脚本与维护文档。协作流程、检查命令和验证矩阵见 [贡献指南](../CONTRIBUTING.md)，源码职责见 [源码导航](../src/README.md)。

- **必须**：安全、正确性、生命周期、证据与协作边界；通过评审落实，不限于自动检查。
- **建议**：可维护性约定；例外需在代码附近或变更说明解释原因。
- **现状/例外**：解释已有实现，不等于鼓励新代码复制历史欠账。

不因建立规范重写历史基线；已有不一致按独立变更逐步处理。具体上限、版本、错误码以实现常量和锁文件为准，规范不维护第二套数值副本。

## 1. 通用约定

### 1.1 命名与文件放置

**必须**：先确定职责和运行环境，再选择目录；不能因为「两处都用」就把系统能力移进浏览器共享层。新增功能先检索已有规则和适配器，避免另写同类校验、布局或进程管理。

**建议**：

| 对象                    | 约定与例子                                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ |
| 文件/目录               | 描述性小写 kebab-case，例如 `job-object.ts`、`utf8-locale.ts`（目标命名，存量仍为 `.mjs`）；保持现有入口命名 |
| 变量/函数/属性          | camelCase；布尔含义清晰，如 `isComposing`、`outputComplete`                                                  |
| 类型/接口/类/React 组件 | PascalCase；不为接口强加 `I` 前缀                                                                            |
| 固定常量/协议错误码     | 表达稳定语义，错误码沿用 `INVALID_SENDER` 这类大写下划线形式                                                 |
| Node 单元测试           | 新建使用 `*.test.ts`；存量 `*.test.mjs` 待迁移，测试名说明条件与预期                                         |
| 桌面集成驱动            | 沿用 `tests/m1/*.ts` 的职责命名，与构建入口同步                                                              |
| npm 脚本                | 通用检查用 `check`/`lint`；探针与产品命令保留既有 `m0:`/`m1:` 名称，不能为命名统一而破坏入口                 |

`workspaceId`、`paneId`、`sessionId`、`generation` 是不同身份，不能缩写成一个容易混淆的 `id` 后跨层传递。

### 1.2 可读性、注释和格式

- **建议**：一个函数负责一项清晰操作；异步、错误和清理分支尤其避免堆成超长单行。拆分应减少理解成本，不为缩短行数创造空洞抽象。
- **必须**：注释解释原因、边界或兼容条件，不把猜测写成已确认根因。版本敏感代码说明适用版本与回归测试。
- **建议**：TODO 写出待解决问题及触发/验收条件；有任务或证据时给路径，不能只留「以后优化」。面向维护者的说明优先中文，API 名称和现有英文测试描述可保留。
- **必须**：新文件使用 UTF-8、两空格、单引号、无行尾分号、LF、末尾换行，其他细节以 [Prettier 配置](../.prettierrc.json) 为准。JSON 保持标准双引号。
- **现状/例外**：存量源码有紧凑写法和不同引号；小修复匹配邻近风格，不顺便整文件格式化。证据文件不适用任何格式规则。

### 1.3 错误、日志和异步资源

- **必须**：外部输入、IPC、原生调用和子进程结果有明确失败路径；不得把未知退出码补成 `0`，不得 catch 后假装成功。
- **必须**：区分业务拒绝、失效会话、超时、进程故障和清理失败；错误需能关联会话/操作，但不泄露敏感输入。
- **必须**：异步调用显式 `await` 或明确安排后续 catch；使用 `void` 不代表可以忽略 rejection。退出路径要能等待必要的在途操作。
- **必须**：监听器、计时器、observer、IPC 订阅、原生句柄和数据库都有所有者和释放路径；初始化中途失败也必须清理，重复 close/dispose 不产生副作用。
- **建议**：错误信息带最小操作上下文；需要定位原始错误时保留 cause/stack，不只重新包装成无上下文字符串。
- **必须**：日志默认不包含终端全文、用户输入、凭据、私人路径/会话内容。显式诊断可记录输入 HEX，不是无敏感信息的天然保证。

## 2. TypeScript、JavaScript 与 Node

### 2.1 文件与模块策略

**必须**：项目自行维护的产品源码、工具脚本和测试默认统一使用 TypeScript；React 使用 TSX。边界按代码职责和真实加载约束划分，不按「纯函数」「文件短」「方便直接运行」划分。

| 范围                           | 目标语言与边界                                                   |
| ------------------------------ | ---------------------------------------------------------------- |
| `src/`                         | TS / TSX；包括布局、校验、流控、键盘、IME、几何与主题等纯逻辑    |
| `scripts/`                     | TS；环境准备、检查、打包、归档和诊断脚本同样适用                 |
| `tests/`                       | TS，React 测试需要 JSX 时用 TSX；不因使用 Node 测试就另选 JS     |
| 工具配置与加载入口             | 优先 TS；当前工具或加载机制确有约束时，按下述例外规则保留 JS/CJS |
| 第三方依赖、生成产物、历史证据 | 不属于自有源码迁移范围，保持原样；证据禁止改写字节               |

#### JS/CJS 例外

- **必须**：新增或正式保留为长期例外的自有 `.js`/`.mjs`/`.cjs`，在本节下记录**具体路径、工具/运行时约束及依据、允许职责、复核或迁移条件**，并在评审中确认；不能只写「兼容需要」。尚未核实的存量文件不是已批准例外。
- **必须**：例外尽量只包含配置声明、加载或启动转接，不继续承载产品逻辑或复杂工程流程；转接 TS 的方式必须受目标运行环境支持，不能直接假定任意 Node 都能执行 TS。
- **必须**：「以前就是 JS」「纯规则复用」「省去执行器配置」不构成长期开口。CommonJS 是模块机制，不等于必须用 JavaScript；先评估 `.cts` 或适用的编译方案。
- **建议**：默认 ESM；Node 内置模块使用 `node:` 前缀。`require`/`createRequire` 可在确有需要的原生模块或兼容接缝中使用，模块选择与源码语言分开判断。
- **必须**：第三方版本通过依赖与锁文件管理，不改 `node_modules` 源码。私有 API 适配写在项目内的受控接缝中。

本轮未批准新的长期 JS/CJS 例外；现有 `eslint.config.mjs`、Node 脚本与探针等仍须在后续迁移时逐项评估，不能据此宣称所有文件都可直接改名。

#### 存量与迁移验收

- **现状/待迁移**：现有 `.mjs`/`.cjs` 按存量管理，不是推荐的新建模式。例如 `src/core/layout/tree.mjs`、`src/shared/workstation/rules.mjs`、`src/renderer/workstation/keyboard.mjs` 属于核心逻辑的优先迁移对象；本轮只更新规范，不迁移源码或改变执行入口。
- **必须**：迁移另开独立变更，补充实际类型并纳入适用的类型检查，不只更换扩展名，也不以批量 `any`/断言制造通过。浏览器、Electron、Node 脚本与测试可使用各自的 tsconfig，不强塞进一个运行环境配置。
- **必须**：新增 TS 脚本/测试或迁移时，同步配置受支持的执行方式、模块路径、测试发现、构建和检查入口；当前只发现 `*.test.mjs` 的入口不能被误认为已经支持 TS 测试。纯解析或运行时类型擦除不等于静态类型检查。
- **必须**：环境准备与故障诊断入口不能依赖尚未准备好的应用构建或原生模块。选择执行方式时核对 Node 版本与语法支持，不为省事自动回退到新建 JS。
- **必须**：保留现有运行时校验、行为回归与原始证据；历史探针迁移需单独授权，不在普通修复中顺手重写保护基线。

### 2.2 类型与运行时边界

- **必须**：类型声明不能代替对 IPC、数据库内容、环境变量和原生消息的运行时校验。尽量复用 `src/shared/workstation/rules.mjs` 的白名单、身份与大小校验。
- **建议**：边界的未知值先用 `unknown`，校验后缩窄；跨进程协议放在 `src/shared/workstation-protocol.ts`，不靠散落的匿名 `any` 传递关键状态。
- **必须**：新增 `any`、非空断言和类型断言仅在已确认契约、外部未提供类型或明确兼容边界使用，附近说明理由并补相应测试；不能用双重断言掩盖没有验证的数据。
- **建议**：用可辨识联合表示互斥状态；`null` 用于明确的空结果，`undefined` 用于未提供/尚未初始化，跨进程序列化时保持一致。
- **现状/例外**：历史存在较多 `any` 和私有成员访问。本轮不批量移除；新规则不冒称已消除全部类型债务。

### 2.3 Node 脚本

- **必须**：路径由明确工程根或脚本 URL 派生，调用外部程序时传参数数组；不把用户路径拼接成 shell 命令。
- **必须**：子进程检查启动错误、退出码和信号，失败向上层传播。需要命令原始证据时保留 cwd、argv、stdout/stderr，不只保留最后一句「通过」。
- **必须**：不隐式下载安装、重建原生模块、覆盖旧输出目录或更改全局环境。临时文件置于明确隔离目录；删除只限本次拥有的路径。
- **建议**：沿用同步编排脚本中 `spawnSync`＋明确失败判断的模式；跨平台测试文件列表由 Node 展开，不依赖 shell 通配行为。

## 3. Electron 分层与 IPC

| 层               | 应负责                                                                  | 不应承担                                                |
| ---------------- | ----------------------------------------------------------------------- | ------------------------------------------------------- |
| main             | 窗口/权限、原生对话框与剪贴板、操作路由、会话归属、配置串行写、退出协调 | 直接接受任意 exec/env/SQL；代替产品服务承接全部原生状态 |
| preload          | 暴露具名白名单 bridge，转发已定义操作，订阅返回取消函数                 | 原始 IPC、Node 对象、任意通道或通用调试执行器           |
| renderer         | React 布局、用户交互、稳定终端宿主、通过 bridge 请求能力                | 直接导入 Electron/Node/原生模块或访问文件系统           |
| core             | 不依赖 Electron/React 的布局与纯规则                                    | 窗口、系统进程、文件访问                                |
| services         | PTY 生命周期、独立 worker、SQLite 单写等受控能力                        | 把不可信消息当成内部可信对象                            |
| adapters/windows | Job/固定句柄、Shell 发现、ConPTY 与原生兼容                             | 污染全局环境、绕过生命周期权威                          |

- **必须**：保留 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true` 以及导航、新窗口、webview/权限拒绝策略；调试方便不能成为放宽理由。
- **必须**：IPC 校验 sender、同一个 mainFrame、精确页面 URL、允许字段、operation、sessionId/generation、归属、尺寸/输入大小和当前状态；不能只校验一个 webContents ID。
- **必须**：主进程确定可用 Shell、cwd 与能力白名单，不将任意可执行路径、env、文件系统或 SQL 暴露给 renderer。
- **必须**：bridge 新增方法同时维护协议、preload、main 校验、订阅释放与正反向测试。用已有结果/错误结构，不另建通用万能调用通道。
- **必须**：剪贴板等外部 API 根据当前版本真实异步契约处理，等待 Promise 后再校验和跨 IPC 返回。
- **现状/例外**：`shared` 不是浏览器安全目录；其中 `io-trace.mjs` 依赖 `node:fs`，`rules.mjs` 用到 `Buffer`。renderer 只能引用已确认浏览器安全的部分，共享类型使用 `import type`。
- **现状/例外**：探针主进程有原生验证代码，不能将产品服务分层规则写成「整个仓库 main 绝不加载原生模块」并据此重构探针。

## 4. React、CSS 与 xterm

### 4.1 组件与状态

- **建议**：React 负责声明布局、表单和可见状态；副作用由明确 effect 或管理器拥有。不要将派生状态再保存一份造成双重事实来源。
- **必须**：effect 的事件订阅/observer/DOM 资源对称清理，处理异步返回时组件已卸载或会话已变化的情况。
- **必须**：终端实例与稳定 DOM 宿主由终端管理器持有；工作区隐藏、重排、分屏比例变化或放大还原不能因 React key 变化而重建会话。
- **建议**：产品快捷键、表单输入与终端输入的处理入口分离；使用语义按钮、明确标签和可见焦点，不让全局快捷键截获输入框的普通编辑。

### 4.2 样式与量测

- **必须**：页面和 xterm 使用同一 palette/主题来源，复用 `palette.mjs`；不要在组件和终端分别维护漂移的颜色表。
- **建议**：使用既有 CSS 变量和局部语义类；避免过宽全局选择器、无理由的 `!important` 及只适配单一截图尺寸的固定布局。
- **必须**：首次创建等待字体和有效布局量测，复用 `geometry.mjs`；隐藏/零尺寸窗格不发送 resize，不用固定 80×24 伪装量测结果。
- **必须**：resize 串行、合并中间值，区分 desired/applied；失败或旧回包不更新为已确认尺寸。字号、CSS 行距、DPR 与 xterm 字格协同验证。
- **现状/例外**：块字符 DOM 绘制与 xterm 私有成员属于锁定版本的适配，不是通用文本处理；升级时重新验证字体、几何、TUI 和输入行为。

## 5. PTY、Windows 生命周期与输入

### 5.1 所有权与清理

- **必须**：broker 是生命周期权威，每个会话独立原生 worker；worker 进入自己的 Job 后才允许创建 PTY。改名/隐藏/重排不等于重建会话。
- **必须**：关闭先停止生产者子树，保留 worker 和读流等待真实 EOF、消费者 ACK、真实句柄退出与 Job 清空；不能用「静默若干毫秒」假装排空。
- **必须**：退出码来自固定进程句柄，正确区分真实退出值和仍运行状态；未知不是成功。超时表示失败或未完成，不能伪造正常关闭。
- **必须**：关闭幂等、可重试；未确认回收前不隐藏失败状态或提前删除窗格。使用自己的 Job/句柄/PID＋创建时间，不按进程名或裸 PID 批杀。
- **必须**：运行环境使用副本，不改系统/用户 PATH、执行策略、profile；发现不到已有 Git for Windows 时明确报错，不静默回退或安装。
- **必须**：终端以用户权限执行命令，不是命令安全沙箱；UI 权限白名单不等于命令内容可隔离任意风险。

### 5.2 流控与尺寸

- **必须**：复用既有输入/输出限额、信用窗口与切块逻辑；字节上限按 UTF-8 计算，不能切断 UTF-16 代理对。不能为修复卡顿而无限扩大缓存。
- **必须**：输出 ACK 在 `xterm.write` 消费回调后发送，不能收到 IPC 就提前确认。保护尾输出和消费者未完成状态。
- **现状/例外**：resize ACK 前通过同一输入句柄写入的中性 NUL fence 是已验证的兼容措施，不是用户输入，也不能当成无用字节删除。

### 5.3 键盘、粘贴与 IME

- **必须**：先确定事件所有权：产品浮层/表单/快捷键与终端各自处理；无产品浮层时 Esc/控制键交给终端。组合输入时不触发产品快捷键，但不能因此吞掉 xterm 的提交键路径。
- **必须**：复用 `keyboard.mjs` 的 `isImeKey` 和现有组合读取适配，不新增另一套组合提交器、文本去重器或输入补发计时器。
- **必须**：连续相同词是合法输入，不能按内容去重；不通过清空原生 textarea、改动 caret、代发用户输入来掩盖增量读取问题。
- **现状/例外**：锁定 xterm 的 `_compositionHelper`/`_textarea` 适配提供追加式读取视图，属于明确的私有版本接缝。升级 xterm/node-pty 必须重跑实际 helper、原生 IME 和正式包回归，不能只测 mock。
- **必须**：Ctrl+C 有选区复制、无选区中断；粘贴走现有 `term.paste` 路径与输入限额，不自行改写换行或绕过 bracketed-paste。
- **必须**：真实候选提交、合成 composition、直接粘入中文是不同测试。不得用粘贴成功证明系统输入法可用。

## 6. SQLite 与持久化

- **必须**：产品数据库由数据服务单写，主进程协调配置写入顺序；renderer 不执行 SQL，不读写数据库文件。
- **必须**：动态值使用参数化语句，写入与读取均验证配置结构；复用已有 preferences/workspace 校验。
- **必须**：schema 使用明确版本，拒绝不支持的未来版本；新增迁移提供旧数据/失败路径测试，不删除用户数据库「解决」兼容问题。
- **建议**：多步必须共同成功的修改使用事务，避免界面先标记成功而落盘失败；考虑故障后重试与数据一致性。
- **必须**：退出释放数据库句柄；测试使用隔离路径，不接管私人 userData。
- **必须**：只存已授权的配置/偏好，不将终端全文、凭据、旧进程树或命令重放队列作为隐式持久化功能。

## 7. 构建、依赖与打包

- **必须**：探针与产品入口、输出和测试保持分离；默认 `build` 仍构建探针，产品使用 `m1:build`，不能让命令名称掩盖实际覆盖范围。
- **必须**：测试入口只在独立测试构建启用；新增入口同步更新构建、测试套件和打包排除/拒绝检查，正式 bridge 不增加通用 debug/exec。
- **必须**：正式打包前生产重建，输出使用新目录；按 receipt、资源锁、原生文件哈希和许可检查，不为省事跳过。
- **必须**：任何 npm 锁变化都会影响 receipt；按 [贡献指南](../CONTRIBUTING.md#锁文件与准备凭据) 新环境流程处理，不能只更新哈希制造有效凭据。
- **建议**：脚本失败给出具体文件/步骤和需要的人工动作；不在失败分支自动下载、替换依赖、覆盖缓存或降低校验强度。

## 8. 测试与原始证据

### 8.1 测试设计

- **建议**：纯规则用 `node:test` 和 `node:assert/strict`；布局/状态序列采用固定种子与可复现输入。用已有工具，不为一个测试另建框架。
- **必须**：覆盖正常、非法输入、边界、并发/旧回包、重复清理和资源失败；测试行为而不只断言源码包含某段字符串。
- **必须**：超时是失败边界，不能无限重试直到绿灯；等待真实条件，不以固定 sleep 代替状态确认。确需系统稳定等待时说明原因。
- **必须**：测试目录、home、Shell rc、数据库和启动进程隔离，不读私人历史、不接管已有会话。GUI 可能抢焦点，粘贴测试可能写系统剪贴板，运行前如实说明。
- **必须**：故障测试区分应用预期崩溃码与监督器成功码，保留对照进程，验证没有误杀；单元测试不是零副作用承诺。
- **必须**：截图只能证明所截时刻的视觉，不能替代焦点、输入、IPC、排空、人工体验或跨机器验证。

### 8.2 证据保真

- **必须**：证据记录实际命令、环境、时间、退出码和原始输出；复用 `scripts/m1/record.mjs`。执行结果不匹配预期时保留原件。
- **必须**：三类证据目录沿用 `.gitattributes` 的 `-text`，包括其中的 Markdown/JSON；不去 ANSI、不修尾空格、不统一换行、不覆盖失败批次。
- **必须**：日志改扩展名以归档时仅改变名称，不改内容；哈希针对原始字节，不对「清洗后的同义文本」计算并冒称原件。
- **必须**：生产默认不持久化终端全文与诊断显式记录输入 HEX 分开说明；诊断只使用已确认无私人信息的隔离数据。
- **必须**：实现、自动验证、原生系统验证、人工体验、打包和远端交付的状态分别记录；旧证据不因代码变化自动变成本轮通过。

## 9. 工具落实范围

| 工具/机制            | 自动落实                                                          | 不能替代                                              |
| -------------------- | ----------------------------------------------------------------- | ----------------------------------------------------- |
| `.editorconfig`      | 支持该标准的编辑器中的文本默认值，证据目录取消自动改写设置        | 编辑器插件额外清理、字节写保护                        |
| Prettier             | 显式纳入清单的格式检查，忽略证据和产物                            | 全仓格式统一、正确性检查                              |
| ESLint               | 基础错误规则、JS 环境区分、renderer 能力导入限制、TS/TSX 语法解析 | TypeScript 类型检查、完整跨层依赖分析、安全审计       |
| `tsc --noEmit`       | 现有 tsconfig include 内的类型检查                                | 所有脚本/测试、产品 Vite 配置和 `.mjs` 的完整类型检查 |
| Node/桌面/正式包测试 | 各自执行范围内的回归                                              | 未执行的原生 IME、人工体验或跨机器验收                |

配置以 [eslint.config.mjs](../eslint.config.mjs)、[.prettierrc.json](../.prettierrc.json)、[.prettierignore](../.prettierignore) 和 [scripts/check.mjs](../scripts/check.mjs) 为准。新增门禁应增加正反向工具回归，先验证当前基线，不能以关闭检查或破坏证据换取绿灯。

**语言策略门禁现状**：TS 优先与 JS/CJS 例外目前由评审执行；现有 `npm run check` 尚未自动限制新增 JS，也未覆盖全部 TS 脚本/测试。后续迁移须同步补齐类型检查和执行入口，不能把本轮文档更新报告成全仓 TS 治理已完成。
